# МедПротокол — MVP ИИ-сервиса медицинской документации

Веб-приложение для транскрипции медицинских приёмов и автоматического заполнения документов по шаблонам.
Стек: **Next.js 16 + TypeScript**, **MongoDB**, **Groq API** (Whisper для распознавания речи, LLM для заполнения шаблонов).

## Сценарий работы

1. Врач создаёт запись приёма (новый или существующий пациент, повод обращения, язык речи: русский / казахский / авто).
2. Фиксирует согласие пациента (текст согласия версионируется; при отказе запись и ИИ недоступны, документы оформляются вручную).
3. Запускает запись с микрофона. Перед записью панель-«светофор» показывает состояние микрофона, интернета (пинг) и сервиса распознавания.
   Звук режется **по паузам в речи** (фрагменты 3–12 с), каждый фрагмент **сначала сохраняется** в MongoDB (GridFS), затем распознаётся — текст появляется через 1–3 с после окончания фразы.
   Реплики автоматически размечаются **«Врач» / «Пациент»**: Whisper делит текст на предложения, LLM назначает каждому говорящего (сам текст модель не меняет). Разметку можно исправить кликом по метке.
   Альтернативы: загрузка аудиофайла (до 4 МБ) или ввод текста вручную.
4. Транскрипцию можно отредактировать.
5. ИИ заполняет выбранный шаблон **только** сведениями из транскрипции:
   - для каждого поля модель обязана привести дословную цитату-источник; если цитаты нет или её нет в транскрипции, поле помечается **«Требует проверки»**;
   - поля без сведений остаются **пустыми** («Нет сведений»), поля вне шаблона отбрасываются.
6. Врач проверяет и редактирует документ. Подтвердить документ можно только после сохранения проверки, без полей «Требует проверки» и с заполненными или явно подтверждёнными обязательными полями, отметив чекбокс «Я проверил(а) документ».
7. Приём завершается, когда все документы подтверждены.
8. Завершённый приём переводится в архив (поиск по ФИО и датам).

Статусы приёма: `draft → recording → processing → review → completed → archived`.
Статусы документа: `draft` (пустой бланк) / `generated` (сформирован ИИ) → `review` → `approved`.

### Надёжность
- Фрагменты отправляются последовательно с повторами (экспоненциальная задержка). Если связь пропала, аудио остаётся в браузере, и его можно отправить повторно. Повторная отправка того же фрагмента не создаёт дубликат.
- Ошибка API распознавания не теряет аудио: фрагмент помечается как ошибочный, кнопка «Распознать повторно» перезапускает распознавание из сохранённого файла.
- После перезагрузки страницы во время записи приём можно продолжить или завершить.
- Правки врача в транскрипции не перезаписываются: новые фрагменты дописываются в конец.
- Удаляются типичные «галлюцинации» Whisper на тишине («Продолжение следует…», «Субтитры сделал…»).

### Безопасность
- Пароли хранятся в виде bcrypt-хеша, сессия — подписанный JWT в httpOnly-cookie (12 ч).
- Врач видит только своих пациентов и свои приёмы. Администратор управляет пользователями и шаблонами и **не имеет доступа** к медицинским записям.
- Изменяющие запросы с чужого домена отклоняются. Включены заголовки безопасности (HSTS, X-Frame-Options и др.).
- Попытки входа ограничены: 5 неудачных попыток за 5 минут.

## Роли
- **Врач**: приёмы, запись, транскрипция, документы, архив.
- **Администратор**: учётные записи (создание, роль, отключение, смена пароля), шаблоны документов (поля, инструкции для ИИ, обязательность, версии).

При первом запуске (пока в базе нет пользователей) автоматически создаются администратор из `ADMIN_*` и демо-врач из `DEMO_DOCTOR_*`, а также три шаблона: «Консультативное заключение (первичный приём)», «Повторный приём», «Памятка с рекомендациями для пациента».

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `MONGODB_URI` | да | строка подключения MongoDB (например, Atlas) |
| `MONGODB_DB` | нет | имя БД, по умолчанию `medscribe` |
| `AUTH_SECRET` | да | случайная строка ≥ 32 символов (`openssl rand -base64 48`) |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME` | да (для первого запуска) | первый администратор |
| `DEMO_DOCTOR_EMAIL`, `DEMO_DOCTOR_PASSWORD`, `DEMO_DOCTOR_NAME` | нет | демо-врач |
| `GROQ_API_KEY` | да | ключ Groq (https://console.groq.com/keys) |
| `AI_BASE_URL` | нет | OpenAI-совместимый API, по умолчанию `https://api.groq.com/openai/v1` |
| `STT_MODEL` | нет | модель распознавания, по умолчанию `whisper-large-v3` |
| `LLM_MODEL` | нет | модель для шаблонов, по умолчанию `openai/gpt-oss-120b` |
| `DIARIZE_MODEL` | нет | модель для разметки «врач/пациент», по умолчанию = `LLM_MODEL` |
| `DIARIZATION` | нет | `off` — отключить разметку по говорящим |

Шаблон: `.env.example`.

## Деплой на Vercel

1. **MongoDB**: создайте бесплатный кластер в MongoDB Atlas (или подключите интеграцию MongoDB Atlas в Vercel Marketplace, тогда `MONGODB_URI` подставится сам). В Network Access разрешите `0.0.0.0/0`: у Vercel нет фиксированных IP.
2. **Groq**: получите API-ключ.
3. На vercel.com: **Add New → Project → Import** репозитория `dammmup/ai-assistant`. Framework определится как Next.js.
4. В **Settings → Environment Variables** задайте переменные из таблицы выше и нажмите **Deploy**.
5. Войдите под `ADMIN_EMAIL` или `DEMO_DOCTOR_EMAIL`.

Регион функций — `fra1` (`vercel.json`). Ограничение Vercel на размер запроса (4,5 МБ) учтено: запись с микрофона отправляется небольшими фрагментами, файлы для загрузки — до 4 МБ.

Через CLI: `npx vercel link && npx vercel env add ... && npx vercel --prod`.

## Локальный запуск

```bash
npm install
cp .env.example .env.local   # заполнить
docker run -d -p 27017:27017 mongo:7   # или MONGODB_URI на Atlas
npm run dev
```

Запись с микрофона требует HTTPS или `localhost`.

## Структура

```
src/lib/            доменная логика: БД, авторизация, ИИ, статусы, правила подтверждения
src/app/api/        REST API (route handlers)
src/app/(app)/      страницы врача и администратора
src/app/print/      печатная форма документа
src/components/     интерфейс; workspace/ — экран приёма, запись с микрофона
```

## Ограничения MVP (по ТЗ)
- Нет интеграции с КМИС/Damumed, ЭЦП, мобильных приложений, мультиорганизационности.
- Разметка «врач/пациент» определяется по смыслу реплик (LLM), а не по голосу, и может ошибаться — врач проверяет её.
- Пословное распознавание «в момент речи» требует потокового STT (Soniox, Deepgram, Speechmatics и др.) — платно; у Groq потокового режима нет.
- Бесплатный тариф Groq: около 20 запросов распознавания в минуту и 7200 секунд аудио в час на организацию — хватает на одного-двух одновременно работающих врачей.
- До работы с реальными пациентами нужно юридически согласовать обработку медицинских данных и их передачу сторонним API (Groq — США). Хостинг, сроки хранения и резервное копирование тоже согласуются отдельно (раздел 13 ТЗ). Для демонстрации используйте тестовые данные.
